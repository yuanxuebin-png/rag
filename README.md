# Pocket-RAG

把一个文件夹里的 md / txt / pdf 变成一个能问答的知识库。问它问题，它去这几份文档里找，找到就答、并且标出这句话来自哪个文件；找不到就直接说没有，不编。

自己拿来做个人笔记检索用的，所以没上向量库，也没接重排模型。各层都能读完，跑起来零配置（有 key 就能跑，没 embedding key 就纯 BM25）。

## 跑出来的数据

| 指标 | 结果 | 说明 |
|---|---|---|
| 检索命中率 | 12/12 | 12 个库内问题的金标小节都进了 top-4 |
| 拒答判定正确率 | 15/15 | 3 个库外问题全部拒答，没有误拒 |
| 答案关键词命中 | 12/12 | 每题一次真实模型调用，答案里有该有的事实 |

评测两种模式：`--offline` 只跑检索和拒答判定，不调模型，几秒完事；不带参数就是全量，会真的调模型。明细在 `docs/eval_result.md`。

## 链路

```
sample_docs/ (md/txt/pdf)
      │  parse.py       md/txt 直接读，pdf 抽文字层（扫描件明确报错，不硬解析）
      ▼
  父子块 (chunk.py)    子块约 200 字，用来定位；命中后把所属父块（整个小节）给模型
      │               小块定位，大块作答
      ▼
  检索 (retrieve.py)   BM25(jieba) 永远可用；配了 embedding key 才走向量通道
      │                两路用 RRF 融合，只看排名；BM25 最高分低于阈值就拒答
      ▼
  答案 (answer.py)     只准依据给定材料作答，结论标 [1][2]，最后回显来源清单
```

## 三件事当时想错了

**一、以为拒答阈值可以拿 RRF 分数来卡。**

RRF 的分数是按排名算出来的，量级只有 0.0x，而且跟相关程度没有绝对关系，拿它做阈值的结果是全拒。后来改成用 BM25 的原始分来卡阈值，RRF 只负责融合排序，不参与判定。

**二、以为接上检索就完事了，结果「怎么做红烧肉」能被答出来。**

库里的笔记一篇都没有菜谱，但它靠疑问词「怎么」在 BM25 上蹭到 4.56 分，直接越过了阈值。加中文停用词表之后这个问题才消掉。这件事让我明白，检索侧的分词和过滤跟阈值是绑在一起的，光调阈值没用。

**三、以为引用是装饰。**

一开始 [1][2] 只是想让答案好看点，后来发现它其实是第二道闸：模型必须把每句结论落到某个片段上，说不清来源的话就不容易写出来。另外拒答的时候压根不调模型，直接从检索这层就断了。

还有一条算不上想错，是取舍：向量通道是可选的。没配 embedding key 就纯 BM25，检索照样能用，上面那组数字就是纯 BM25 跑出来的。副业项目不该因为缺一个 key 就残废。

## 怎么跑

```bash
# 依赖 python 3.13+、langchain 1.x、rank-bm25、jieba、pdfplumber
cp .env.example .env        # 填 DeepSeek key；SiliconFlow key 可选，用来开向量通道

# 交互问答 / 单问
python -m pocket_rag.cli
python -m pocket_rag.cli "DeepSeek 上 max_tokens 怎么写才生效"

# HTTP 接口，给 patch-agent 的 query_knowledge 工具用
python -m pocket_rag.api            # 默认 127.0.0.1:8765，POST /query + GET /health

# 评测：先离线，再全量
python -m pocket_rag.evals --offline
python -m pocket_rag.evals
```

想拿它当自己的知识库用，把 `pocket_rag/cli.py` 里的 `docs_dir` 指到你的文件夹就行。

## 目录

```
pocket-rag/
├── pocket_rag/
│   ├── parse.py        # 多格式解析（坏文件记进错误清单，不拖垮索引）
│   ├── chunk.py        # 父子块切分（滑窗子块 + 段落续切长父块）
│   ├── retrieve.py     # 混合检索 + RRF + 拒答
│   ├── answer.py       # 带引用编号的答案
│   ├── api.py          # HTTP 接口（标准库实现）
│   ├── evals.py        # 15 条评测（三层判定，支持 --offline）
│   └── cli.py          # 命令行入口
├── sample_docs/        # 示例知识库（5 篇笔记 + 1 个脚本生成的 PDF）
└── docs/eval_result.md # 评测留档（自动生成）
```

## 已知的坑

图片文件（png / jpg）目前是被静默跳过的，既不入库也不进错误清单，这个行为和扫描件 PDF 对不上（后者会明确报错）。打算在 v2 一起改。
